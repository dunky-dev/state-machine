# @dunky.dev/native-rust

Private. The Rust engine for React Native.

Hermes has no WebAssembly, so React Native cannot load the wasm build. Instead
it links the Rust crate [`crates/uniffi`](../../crates/uniffi) (`dunky-uniffi`)
as native code and calls it over JSI. The bindings and the turbo-module glue are
generated by
[uniffi-bindgen-react-native](https://jhugman.github.io/uniffi-bindgen-react-native/)
(ubrn). The Rust side speaks the handle protocol of `crates/wasm`, with values
as JSON strings, so the wasm adapter (`@dunky.dev/state-machine-wasm`) drives it
unchanged.

```
crates/uniffi  (PaletteMachine: crates/demo's palette, uniffi proc-macros)
      |
      |  pnpm ubrn:ios / pnpm ubrn:android
      v
build/NativeRustFramework.xcframework    static lib, iOS device + simulator
android/src/main/jniLibs/<abi>/          static lib, 4 Android ABIs
cpp/ ios/ android/ NativeRust.podspec    JSI + turbo-module glue
src/generated/                           TypeScript bindings + module entry
      |
      |  src/index.ts: NativePaletteHandle -> fromWasm
      v
a Machine for useMachine (sandbox/native, "Engine: Rust")
```

Only `src/index.ts`, `package.json`, `ubrn.config.yaml`, `tsconfig.json` and
this README are hand-written; everything else is generated and gitignored.

```ts
import { createNativePalette } from '@dunky.dev/native-rust'

// Same events, context and computed values as the TS palette config.
const source: CommandPaletteSource = props => createNativePalette(props.commands)
```

`loadNativeRust()` throws, with the reason, when the app does not carry the
module (Expo Go, or no ubrn build yet); `createNativePalette` calls it. A JS
reload does not pick up Rust changes: rebuild the libraries, then the app.

## How to rebuild

Once per machine:

```sh
rustup target add aarch64-apple-ios aarch64-apple-ios-sim \
  aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
cargo install cargo-ndk
```

iOS needs Xcode and CocoaPods. Android needs `ANDROID_HOME` with NDK
27.1.12297006, and JDK 17.

After a change in `crates/uniffi` (or the crates it uses):

```sh
cargo test --manifest-path crates/uniffi/Cargo.toml
pnpm -C packages/native-rust ubrn:ios       # xcframework + bindings
pnpm -C packages/native-rust ubrn:android   # jniLibs + bindings
```

These are debug builds; append `--release` for optimized Rust. The first run
also compiles the ubrn CLI. `pnpm -C packages/native-rust ubrn:clean` deletes
the generated files.

Then rebuild the app. `pnpm -C sandbox/native ios` (`expo run:ios`) does all of
it; the explicit, non-interactive steps are:

```sh
cd sandbox/native
pnpm exec expo prebuild --platform ios --no-install
(cd ios && pod install)
xcodebuild -workspace ios/cmdk.xcworkspace -scheme cmdk -configuration Debug \
  -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath ios/build/DerivedData build
pnpm exec expo start   # Metro, for the debug build

pnpm exec expo prebuild --platform android --no-install
(cd android && ./gradlew assembleDebug)
```
